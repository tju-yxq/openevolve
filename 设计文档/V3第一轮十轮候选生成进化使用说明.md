# V3 第一轮十轮候选生成进化使用说明

> 版本状态：第一轮可运行版  
> 适用分支：`codex/v3-mapping`  
> 官方 V3 基准提交：`a7300c58df683dc99cb48027d5bfd4c887486c48`  
> 默认进化轮数：10 轮

## 一、当前可以完成什么

当前版本已经打通以下闭环：

```text
官方 Equiformer V3 模型配置
    -> 两层或多层 Energy+Force Typed DSL 基线
    -> GLM 选择一个已认证的局部变异动作
    -> 物化为完整 Typed Patch
    -> 原子提交式应用补丁
    -> TypeChecker 类型检查
    -> 与更新后 V3 规格重新生成的程序做语义身份核对
    -> 通用 e3nn Graph Lowering 支持检查或实际构建
    -> 保存候选、规范化程序、补丁、假设和 Lowering manifest
    -> 以上一轮候选为下一轮父代，连续执行 10 轮
```

第一轮不是让 LLM 任意重写 190 个节点。LLM 负责在已经过合同审计的变异目录中选择动作并提出待验证假设，程序负责把动作物化为 Typed Patch，并拒绝越界或不一致的修改。

## 二、第一轮开放的变异范围

第一轮只开放六类保持参数形状的 V3 随机计算路径：

| 变异族 | 同步修改的实际 DSL 节点 |
| --- | --- |
| `alpha_drop` | 每个 Block 的 alpha 标量 dropout |
| `attn_weights_drop` | 每个 Block 的注意力权重 dropout |
| `value_drop` | 每个 Block 的标量 SwiGLU 与 S2 网格值路径 dropout |
| `drop_path_rate` | 每个 Block 的 Attention 与 FFN 图级随机深度 |
| `proj_drop` | 每个 Block 的 Attention 与 FFN 等变投影 dropout |
| `ffn_drop` | 每个 Block 的 FFN 标量与 S2 网格 dropout |

每次修改同时更新：

1. 所有受影响运行时节点的属性；
2. `program.parameters.equiformer_v3_spec` 中对应的官方规格字段；
3. Typed Patch 的前置条件、后置条件、父代架构身份和编辑范围。

补丁应用后，系统会重新根据更新后的 `EquiformerV3Spec` 生成完整 V3 程序，并要求两者的规范化架构 ID 完全一致。这用于防止只改一部分节点、漏改另一条随机路径或留下陈旧规格元数据。

## 三、导出 V3 Typed DSL 基线

模型配置可使用 JSON 或 YAML，`model` 区域必须能被严格导入为基础版 `equiformer_v3`，当前不接受 DeNS。

```powershell
python scripts/export_dsl_v3_seed.py `
  --model-config configs/dsl_v3_first_round_smoke.json `
  --output output/v3_seed
```

主要输出：

- `equiformer_v3_seed.dsl.json`：未经变异的 V3 Typed DSL；
- `model_identity.json`：官方规格身份、DSL 架构 ID、节点数、输出和导入字段清单。

## 四、使用 GLM 连续进化 10 轮

调用凭据只从环境变量读取，不写入配置、日志或证据目录。

```powershell
$env:GLM_API_KEY = "由安全环境注入，不要写入仓库"

python scripts/run_dsl_v3_evolution.py `
  --model-config configs/dsl_v3_first_round_smoke.json `
  --output output/v3_glm_10_rounds `
  --rounds 10 `
  --selection-mode glm `
  --model glm-5.2 `
  --validation-level static `
  --equiformer-v3-root C:\path\to\equiformer_v3_official
```

如果服务器已经设置 `EQUIFORMER_V3_ROOT`，可以省略最后一个参数。`--validation-level static` 会完成类型检查、逐节点 Lowering 支持和组合闭合检查，但不为每一轮实例化模型，适合先快速生成候选。

断点恢复使用：

```powershell
python scripts/run_dsl_v3_evolution.py `
  --model-config configs/dsl_v3_first_round_smoke.json `
  --output output/v3_glm_10_rounds `
  --rounds 10 `
  --selection-mode glm `
  --validation-level static `
  --resume
```

恢复时会核对编译器语义、后端语义、V3 官方提交、seed 架构 ID、模型、选择模式、验证等级和 V3 源码路径。身份发生变化时拒绝续跑。

## 五、候选输出结构

每一轮目录包含：

```text
round_001/
├── candidate.dsl.json
├── candidate.canonical.dsl.json
├── patch.json
├── selection.json
└── lowering_manifest.json
```

根目录包含：

- `seed.dsl.json`：第 0 轮父代；
- `evolution.jsonl`：完整父子链、动作、假设和身份；
- `run_manifest.json`：不可静默改变的运行合同；
- `heartbeat.json`：当前完成轮数；
- `summary.json`：候选数量、唯一性和第一轮边界。

`candidate.dsl.json` 保留稳定源节点名，供下一轮 Typed Patch 定位；`candidate.canonical.dsl.json` 用于规范化审计和跨运行身份比较。

## 六、重新验证候选的通用 Lowering

对全部 10 个候选执行实际模型构建：

```powershell
python scripts/validate_dsl_v3_evolution.py `
  --run output/v3_glm_10_rounds `
  --scope all `
  --validation-level build `
  --equiformer-v3-root C:\path\to\equiformer_v3_official
```

对最终候选执行构建、Energy/Force 前向、反向和旋转等变性检查：

```powershell
python scripts/validate_dsl_v3_evolution.py `
  --run output/v3_glm_10_rounds `
  --scope final `
  --validation-level full `
  --equiformer-v3-root C:\path\to\equiformer_v3_official
```

这里的通用 Lowering 不调用官方 `EquiformerV3_OC`、`TransBlockV3`、`EquivariantGraphAttention` 或 `ScalarFeedForwardNetwork` 构造器。它仍会使用 e3nn 和已经冻结的官方低层数学算子实现，例如 Wigner 旋转与 S2 Grid；这属于逐原语 Lowering 的可信运行时依赖，不是整网旁路。

## 七、本次真实十轮结果

证据目录：`reports/dsl_v3_first_round_glm_evolution_20260801/`

结果如下：

- GLM 实际完成 10 轮，未使用确定性回退；
- 10 个候选架构 ID 全部不同；
- 每个候选均为 190 个 Typed DSL 节点；
- 10 个候选均能由通用 Lowering 实际构建；
- 每个候选均为 33,498 个可训练参数，说明第一轮未改变参数形状；
- 所有候选的 unsupported node 与 composition error 均为空；
- 所有候选均未出现官方整网、Block、Attention 或任务头构造器旁路；
- 最终候选架构 ID 为 `b6b9058c1216264d`；
- 最终候选 Energy 输出形状为 `[1]`，Force 输出形状为 `[4, 3]`；
- 最终候选位置梯度和全部可训练参数梯度均存在且有限；
- 最终候选旋转后 Energy 最大绝对误差约为 `9.31e-10`；
- 最终候选旋转后 Force 最大绝对误差约为 `2.35e-7`。

这些结果证明候选合法、可 Lowering、可微且满足当前旋转等变性数值门禁，但不证明候选性能优于父代。

## 八、当前不能宣称什么

第一轮仍不能宣称：

1. 已经发现性能更优的 V3，因为尚未进行统一训练预算下的候选排序；
2. 已经开放任意结构创新，因为当前只搜索六类随机计算路径；
3. 已经支持改变宽度、头数、分辨率、层数或参数树；
4. 已经支持形状变化后的通用部分 checkpoint 继承；
5. 已经完成 Stress Head；
6. 已经完成生产宽度和精确短训练轨迹验收。

因此，第一轮的准确表述是：

> 已经完成 V3 Energy+Force Typed DSL 的十轮 LLM 受限候选生成闭环。候选由 Typed Patch 修改、类型系统约束并由通用 Lowering 构建；当前搜索维度限定为保持参数形状的六类随机计算路径，候选性能仍需训练实验决定。

## 九、第二轮计划

第二轮按以下顺序推进：

1. 接入统一 V3 训练 evaluator，对 seed 和 10 个候选使用相同数据、种子、步数和评估协议；
2. 实现参数形状不变候选的 checkpoint 安全继承审计；
3. 开放激活、归一化、局部读出和残差路径等更具结构性的 Typed Patch；
4. 实现宽度、头数、分辨率和层数变化后的部分参数继承；
5. 加入多样性、编辑距离、功能差异和低质量候选淘汰机制；
6. 再扩展 Stress Head、生产宽度和短训练轨迹门禁。
