# LLM驱动等变网络架构自进化的CCF A会议论文潜力评估

> 评估日期：2026年7月24日  
> 评估对象：面向三维分子学习的等变架构DSL、可信编译器与LLM驱动架构自进化方法  
> 结论性质：研究定位与投稿门槛判断，不是录用概率预测

## 1. 结论

这个课题可以发展为一篇CCF A类会议论文，但必须完成一次研究重心升级。

当前容易形成的版本是“用四因子`ArchitectureSpec`约束LLM搜索Equiformer V1已有配置，并在QM9极化率任务上训练候选”。这个版本具有工程价值和实验价值，但作为CCF A主会论文，容易被评价为搜索空间较窄、方法组合性强、任务单一，并且没有证明LLM比传统搜索更有效。

具备A类竞争力的版本应当回答一个更一般的问题：

> 如何把等变神经网络表示成一种可由LLM生成、可由编译器验证、可自动转换为可训练模型的领域专用语言，并在固定计算预算下利用实验反馈进化出人工搜索空间之外的新等变算子或拓扑？

因此，本课题的论文主体不能是“OpenEvolve+SPARK+Equiformer的集成”，也不能只是“LLM调节超参数”。论文需要以等变架构DSL、可信编译与认证、证据驱动的LLM程序搜索作为三个相互依赖的方法贡献。

## 2. 最有希望的论文主张

建议将论文主张组织为以下形式：

> 我们提出一种保持等变语义的神经架构DSL及其可信编译器，使LLM能够组合表示、等变算子、特征更新与网络拓扑，同时在编译期拒绝类型错误和破坏等变性的候选。基于编译结果、训练轨迹和谱系证据，LLM进化搜索在相同GPU预算下获得比随机搜索、传统进化搜索和自由代码编辑更高的合法候选率、更高的搜索效率，并发现经完整训练验证的新等变结构。

这个主张包含四个可以被实验推翻的命题：

1. DSL能够表达的不只是已有Equiformer超参数组合，还包括新的算子组合或计算拓扑。
2. 编译器能够在训练前发现大多数非法候选，同时不会拒绝大量合法候选。
3. LLM使用历史证据后，在相同候选数、GPU时间和训练预算下优于非LLM搜索。
4. 搜索发现的结构在完整训练、多个随机种子和多个三维任务上仍然有效。

只要其中任何一个核心命题没有证据，A类审稿人都可能把工作降格为工程框架或单数据集案例研究。

## 3. 与最接近工作的区别必须是什么

ICLR 2023已经接收了《Equivariance-aware Architectural Optimization of Neural Networks》。该工作提出等变性松弛变换、混合不同群约束的层，并使用进化及可微NAS优化近似等变约束。因此，“我们首次搜索等变网络架构”不能作为本文创新点。

本课题需要建立以下差异：

| 维度 | 已有等变架构优化 | 本课题应达到的贡献 |
|---|---|---|
| 搜索对象 | 群约束及等变程度 | 可组合的等变算子、表示流和拓扑程序 |
| 候选表示 | 预定义连续或离散搜索变量 | 具有语法、类型和语义的DSL程序 |
| 生成器 | 进化或梯度优化 | 使用实验历史进行推理和修复的LLM |
| 正确性 | 由预定义层和搜索空间保证 | 静态类型检查、等变语义检查和动态审计共同保证 |
| 创新范围 | 在预设空间内优化约束 | 生成预设模板组合之外的新算子或结构 |
| 成本治理 | 常规NAS预算 | 面向昂贵三维模型的多保真校准与GPU预算控制 |

OpenEvolve主要提供通用代码进化和种群基础设施；SPARK主要提供反思后再编辑以及搜索区域选择思想。它们是基础设施和方法来源，不应被包装为本课题的原创贡献。本课题的原创部分必须落在等变DSL、编译语义、等变认证和昂贵架构搜索策略上。

## 4. 当前版本为什么还不足以直接投A类

### 4.1 DSL表达能力不足

当前四因子可以安全表达Equiformer V1构造参数和若干协同配置，但尚不能可靠表达新张量积路径、新消息传递算子、多分支拓扑或逐层不可约表示流。它更接近类型化架构配置语言，而不是能够支持新算子发现的完整架构语言。

### 4.2 编译器保证尚不完整

当前Builder可以把合法规格映射为官方Equiformer模块，也有旋转、平移和排列审计，但还没有针对新算子的形式化类型系统、组合语义和可说明的等变保持结论。最终输出的数值审计不能完全替代算子级正确性说明。

### 4.3 LLM搜索优势尚未成立

合法候选率提高只能说明约束有效，不能证明LLM能够找到更好的架构。必须在等计算预算下与随机DSL搜索、传统进化搜索以及不使用历史反思的LLM搜索比较。

### 4.4 单一任务不足以支持一般方法

只在QM9的极化率目标上获得更低MAE，可能只是针对单个标量任务的搜索结果。一般方法论文至少需要覆盖多个QM9目标，并加入包含力或向量输出的任务，以验证方法不是只适用于旋转不变标量预测。

## 5. 达到A类标准需要补齐的方法

### 5.1 第二代等变架构DSL

DSL至少需要包含：

- 类型：标量、向量及高阶不可约表示；
- 原语：径向函数、球谐函数、张量积、等变线性层、门控、注意力和归一化；
- 组合子：串联、残差、并联、聚合、条件门控和层级堆叠；
- 拓扑：消息路径、分支连接、跨层连接及逐阶段表示配置；
- 约束：输入输出类型、宇称、角动量耦合、最终观测量类型及资源上限；
- 规范化：语义等价候选的标准形式、稳定哈希、去重和缓存。

### 5.2 可信编译器与认证

编译链应明确区分：

```text
DSL源码
→解析器
→抽象语法树
→类型与irrep流检查
→等变语义检查
→资源与协议检查
→规范化中间表示
→PyTorch/e3nn后端
→数值等变审计
```

论文需要给出至少一个可说明的性质：如果每个原语满足指定群作用下的等变性，且组合通过类型规则，那么编译后的复合网络保持相应等变性。数值审计用于发现实现错误和浮点问题，而不是替代语义规则。

### 5.3 证据驱动的LLM搜索

LLM每次生成候选时应接收父代、参考候选、结构差异、训练轨迹、失败原因、资源成本和因子收益。需要区分“LLM带来的推理收益”和“进化算法本身的收益”，并控制模型调用次数与token成本。

### 5.4 多保真选择的可信度

短训练只能在其候选排序与完整训练排序达到预注册阈值后用于晋级。论文应报告Spearman相关性、Kendall相关性、top-k召回率和选择后悔值，而不能只展示一条表现较好的早期曲线。

## 6. 必须完成的实验矩阵

### 6.1 搜索方法对照

| 方法 | DSL约束 | LLM | 历史反思 | 进化谱系 |
|---|---:|---:|---:|---:|
| 随机DSL搜索 | 是 | 否 | 否 | 否 |
| 传统进化DSL搜索 | 是 | 否 | 否 | 是 |
| 无反思LLM搜索 | 是 | 是 | 否 | 是 |
| 完整方法 | 是 | 是 | 是 | 是 |
| 自由代码编辑 | 否 | 是 | 可选 | 是 |

所有方法必须共享候选数、GPU小时、训练step、数据划分和最终完整训练名额。

### 6.2 架构基线

至少包含原始Equiformer、EquiformerV2、典型SE(3)/E(3)等变模型、人工调参Equiformer以及参数量匹配的搜索基线。比较时同时报告MAE、参数量、训练吞吐、推理延迟和峰值显存。

### 6.3 数据与任务

建议采用三级证据：

1. QM9多个标量目标，用于低成本搜索与跨性质泛化；
2. MD17或rMD17的能量和力预测，用于验证向量输出与微分一致性；
3. 一个更大规模三维任务，用于验证方法是否能够扩展。若算力不足，应明确将其作为扩展实验，而不是用单个QM9目标代替一般性证据。

### 6.4 统计与复现

搜索算法需要多个search seed；最终候选需要多个training seed。论文应报告均值、标准差、配对比较、完整候选谱系、失败候选、总GPU小时、LLM调用量和最终测试集使用次数。

## 7. CCF A会议匹配判断

根据CCF于2026年3月31日发布的第七版目录，AAAI、NeurIPS、ICML和ICLR属于人工智能A类会议；IJCAI在该版目录中属于B类。

| 排名 | 会议 | 匹配分 | 适合的论文版本 | 核心风险 |
|---:|---|---:|---|---|
| 1 | ICLR | 90/100 | 等变表示、DSL、编译与新架构发现形成统一方法 | 只做配置搜索会被认为创新不足 |
| 2 | ICML | 86/100 | 强调一般机器学习方法、形式化语义和严格等预算实验 | 单一分子任务难以证明普适性 |
| 3 | NeurIPS | 84/100 | 强调LLM程序搜索、物理科学应用和大规模实证 | 组合式系统容易被质疑缺少核心算法 |
| 4 | AAAI | 72/100 | 强调AI智能体、程序合成和自动科学发现 | 几何深度学习方法深度可能不如前三者匹配 |

匹配分是投稿适配度，不是录用概率。

截至2026年7月24日，AAAI-27摘要截止时间已于2026年7月21日结束，无法再注册新的主会投稿；全文截止为2026年7月28日。ICLR 2027官方征稿页尚未发布。ICML 2026和NeurIPS 2026已经截稿，下一届官方日期尚未公布。因此，不建议为了最近截止日期压缩方法；更合理的是以ICLR、ICML或NeurIPS的后续完整周期为目标。

## 8. 建议的论文完成判据

满足以下条件后，可以合理地把目标设为CCF A主会：

- DSL能够生成至少一类现有四因子规格无法表达的新算子或拓扑；
- 编译器具有清晰的类型规则、等变组合规则和动态审计；
- 完整方法在等GPU预算下稳定优于随机及传统进化搜索；
- 至少一个搜索发现经过完整训练和多随机种子复验；
- 不只在QM9极化率上有效，并覆盖不同性质或输出类型；
- 完整报告无效候选、搜索成本、LLM成本和失败案例；
- 与ICLR 2023的等变架构优化工作形成明确方法差异。

如果最终只能完成四因子配置搜索、QM9单目标和少量候选全量训练，应把论文定位为阶段性系统或应用工作，而不应直接按A类方法论文包装。

## 9. 最终判断

这个课题不是天然的CCF A论文，但它具有清晰的A类成长路径。决定论文等级的不是是否使用LLM、OpenEvolve或SPARK，而是是否真正完成以下闭环：

```text
可表达新结构的等变DSL
→具有语义保证的可信编译器
→利用实验证据生成候选的LLM搜索
→等预算下优于强搜索基线
→发现可复现、可泛化的新等变架构
```

若这个闭环成立，论文可以以ICLR为首选、ICML和NeurIPS为主要备选；若闭环只完成前三分之一，则更适合作为后续完整论文的系统原型。
